# Vibe Lube

[![CI](https://github.com/eliem08/vibe-lube/actions/workflows/ci.yml/badge.svg)](https://github.com/eliem08/vibe-lube/actions/workflows/ci.yml)

> **Quick fixes for apps built with AI, before they leak your keys.**

**Who it's for:** Non-technical founders who built an app with AI coding tools.

**The problem:** AI-built apps ship with exposed secrets, unignored .env files, risky code and no tests, and the founder can't see it.

**What you get:** Inspect a repo for leaked secrets, env exposure and risky code, get a graded report with a fixed-price quote, and apply the safe fixes automatically.

## Quickstart

Customers receive a release archive with the wheel and the examples. Python 3.10+ and no other dependencies.

```bash
pip install vibe_lube-0.1.0-py3-none-any.whl
vibe-lube inspect .
vibe-lube inspect . --json
```

## Web app and API

Every command is also a JSON API endpoint and a browser form, served by the built-in web app.

```bash
vibe-lube-web --port 8000          # then open http://127.0.0.1:8000
vibe-lube-web keys create --label "first customer"   # prints an API key (stored hashed)
docker build -t vibe-lube . && docker run -p 8000:8000 -e API_KEYS=sk_... -v vibe-lube-data:/data vibe-lube
```

Every API call needs `Authorization: Bearer <key>` once any key exists; a server on a public address refuses to start without one. Calls are rate-limited per key (60/min, `--rate`) and metered: `vibe-lube-web usage` prints calls per key for billing.

Endpoints: `POST /api/inspect`, plus `GET /healthz` and `GET /api/spec` (machine-readable field list).
Files are sent as `{"name": ..., "content": ...}`, folders as `{"files": [...]}` or a base64 zip.

## What it does

- **Inspection** of a project directory (skips `node_modules`, `.git`, build output):
  - **secrets**: OpenAI / Anthropic / AWS / GitHub / Slack / Stripe keys,
    private key blocks, generic `api_key = "..."` assignments
  - **env hygiene**: `.env` present but not git-ignored; env vars referenced in code
    but no `.env.example`
  - **client-side exposure**: `NEXT_PUBLIC_` / `VITE_` vars named like secrets,
    Supabase `service_role` in client code
  - **supply chain**: `package.json` without a lockfile, `"*"` / `"latest"` versions
  - **risky code**: `eval(`, SQL built with string concatenation / f-strings,
    `CORS(*)` / `Access-Control-Allow-Origin: *`, `debug=True`
  - **maintainability**: no tests, no README, 1,000+ line files, stray `console.log`, TODOs
- **Health score** (0–100) and grade, findings grouped by severity
- **Service menu**: each finding maps to a fix with an estimated time/price
- **`--fix`**: safe auto-fixes only — add `.env` to `.gitignore`, generate `.env.example`
  from referenced variable names (never values)

## Development

Zero runtime dependencies; Python 3.10+.

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python -m unittest discover -s tests -t .           # unit + CLI smoke tests
ruff check . && ruff format --check .               # lint + format
```

```
vibe_lube/core.py       domain logic (pure, importable, fully tested)
vibe_lube/__main__.py   CLI (`vibe-lube ...` / `python -m vibe_lube ...`)
tests/                unit tests + generated CLI smoke tests
```

CI runs lint and tests on Ubuntu and Windows across Python 3.10, 3.12 and 3.13.
